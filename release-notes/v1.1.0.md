## A more convenient desktop player

- Entire interface in English, including menus, tooltips, accessibility labels and errors.
- New horizontal compact layout alongside a scalable normal layout; both keep restart, previous, play/pause, next and seek controls.
- Window position, size, layout, album visibility and locked opacity are remembered beside the executable.
- Off-screen window recovery and optional snapping to screen edges, with an unlock button that follows the actual lock control.
- Notification-area menu: show/hide, lock/unlock, settings and exit.
- Configurable global shortcuts, defaulting to **Ctrl+Alt+P** (show/hide) and **Ctrl+Alt+U** (unlock and show). Shortcut conflicts are reported.
- Adjustable locked opacity with a live preview in Settings, plus an option to hide album metadata.
- Full title, artist and album tooltips when unlocked; clear playback states and an **Open Spotify** action when disconnected.

## Playback fixes

- Commands handle exceptions and rejected operations without crashing the player.
- Each control follows the capabilities Spotify actually exposes.
- Seeking supports mouse and keyboard, previews the chosen time, and rejects a seek if the track changed during selection.
- Disconnection clears previous artwork, metadata and playback times; reconnection is automatic.
- Artwork is retried after temporary failures or late availability.
- Media-session events refresh metadata and playback state promptly; the timer animates progress and performs periodic recovery.

## Download

Download **SpotifyPopup.exe** and place it in a writable folder. This is a single self-contained executable for 64-bit Windows 10 version 2004 or later, or Windows 11. No separate .NET installation, Spotify developer account or API credentials are required.

The app creates `SpotifyPopup.settings.json` beside itself when saving preferences. If that folder is not writable, the app remains usable and reports that preferences could not be saved. As with previous versions, .NET extracts native components to the temporary directory at runtime.

## Verification

The release pipeline runs playback/persistence regression checks, isolated Windows UI checks, standalone startup/shutdown verification, and executable icon checks before publishing. Windows UI checks use a simulated media controller and do not modify a user's Spotify playback. Real Spotify playback, screen-reader behavior and mixed-DPI multi-monitor interactions still require hands-on validation on a Windows desktop.
